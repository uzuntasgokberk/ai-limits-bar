# Security policy

AI Limits Bar runs as your user every few minutes and handles sign-ins to several AI services, so it is built to do as little as possible with them.

## Report a vulnerability privately

Use GitHub's private vulnerability reporting: the repository's **Security** tab, then **Report a vulnerability** ([direct link](https://github.com/uzuntasgokberk/ai-limits-bar/security/advisories/new)). Do not open a public issue, discussion or pull request for a security problem.

Include:

- your macOS, SwiftBar and Python versions (the Python the launcher uses: the first of `/opt/homebrew/bin/python3`, `/usr/local/bin/python3` and `/usr/bin/python3` that exists);
- the provider concerned, if any, and its tool's version;
- the smallest reproduction, with fake values: the file and line, what an attacker controls, and what happens.

**Never send secrets or data**, in a report or anywhere else: no tokens or other credentials, no `config.json`, no files from `~/Library/Caches/ai-limits-bar/`, no account, tenant or subscription ids, no resource or deployment names. Reproduce with fake values; if a real credential was exposed, sign out and in again with the provider's own tool first.

This is a personal project maintained on a best-effort basis. Fixes go to the latest `main` only; update with `git -C ~/ai-limits-bar pull`.

## What counts

- A credential is written to disk, logged, printed, put in the cache or a process argument, or sent anywhere but its own provider.
- A write endpoint or method is called, i.e. anything that changes an account (for example using a limit reset).
- External text (a provider's answer, a cache file, a setting) adds a menu action, a parameter or a whole menu line. The one deliberate exception is a limit's name in a *Menu bar shows* entry: it must pass the allow-list described under *Guarantees*, `--show` checks it again, and it can only set `menu_bar`; a name that does more counts. Foundry deployment names reach the *Foundry prices…* window only as `osascript` arguments and never come back from it; a name that changes the script or what is written counts. The same goes for the menu bar strip's drawing: a value that changes its script, or anything other than the two checked images reaching the menu bar line, counts.
- The environment or a SwiftBar link changes behaviour beyond triggering a refresh (for example turning a provider on or off, or sending a request through a proxy).
- A file is written outside the documented ones (see *Files written* below).

The documented limits are not vulnerabilities: the endpoints are unofficial and can change or break; a process running as the same user can read the same files and Keychain item this tool reads; Foundry's *Details* submenu shows deployment and invoice meter names (see *Privacy* below).

## Guarantees

- **No credential is ever refreshed, stored, logged or printed.**
  - Claude: the OAuth access token is read from Claude Code's Keychain item and travels only in the HTTPS request header to `api.anthropic.com`. If the token has expired, the menu asks you to open Claude Code; this tool never refreshes it, because a second client refreshing could sign Claude Code out.
  - Codex: no credential is read. A short-lived `codex app-server` is asked for rate limits; Codex manages its own session.
  - Gemini (Antigravity): no Google credential is read. The local server's port and CSRF token are read from its 0600 file, and the requests go only to `127.0.0.1`, never through a proxy. The file must be a regular file owned by you that others can't read; anything else (a symlink, a world-readable file) is ignored. The Gemini CLI fallback uses its saved token only while it is still valid, and never refreshes it.
  - GitHub Copilot and Microsoft Foundry: the GitHub CLI and Azure CLI own their credentials.
- **Read-only towards your accounts.** The only thing this tool changes is its own settings file, `config.json`, when you turn a provider on or off, choose what the menu bar shows or set Foundry prices.
  - Every message to Codex goes through an allow-list of two requests (`initialize`, `account/rateLimits/read`) and the `initialized` notification, so methods such as the one that consumes a reset credit cannot be sent.
  - Claude's reset endpoint is never called.
  - Antigravity's local server is asked only two read requests: `GetUserStatus` (plan and per-model quotas) and `RetrieveUserQuotaSummary` (the quota groups and their 5-hour and weekly windows), the latter with an empty body, never `forceRefresh`. The server fetches the numbers from Google with its own session.
- **Environment.**
  - SwiftBar copies the query parameters of a refresh link into the plugin's environment, and any web page or app can open such a link. The plugin therefore does not trust its environment.
  - Neither its regular runs nor the menu's click commands go through a login shell: with `runInBash` off, SwiftBar starts the file directly with its arguments. The launcher runs under `zsh -f`, which reads no startup files and imports no functions; it uses only shell builtins and starts Python with an empty environment (`env -i`) in isolated mode (`-I`). The only thing passed on is whether *Refresh now* was clicked. The click commands of *Providers…*, *Menu bar shows* and *Foundry prices…* get the same plugin environment, so the same rules apply to them.
  - Python and the tools it starts (`security`, `codex`, `gh`, `az`, `osascript`) get a fixed environment: the home folder from the user database, a fixed `PATH` and locale. Proxies, `HOME`, certificate settings and the like are never inherited.
  - Switches are command-line arguments, which a link cannot set. SwiftBar passes none on its regular runs; the only ones it ever passes come from this plugin's own *Providers…*, *Menu bar shows* and *Foundry prices…* items (`--choose`, `--show highest` / `--show PROVIDER:LIMIT`, or `--prices`, plus `--config` if one was given). A refresh still uses values read less than a minute ago, and the one right after a *Providers…*, *Menu bar shows* or *Foundry prices…* click (Save or Cancel) uses the values already read, whatever their age; it reads only a provider that has none yet and, after a price change, Foundry (not forced).
- **Subprocesses** run without a shell, with fixed arguments and absolute paths.
  - The *Providers…* window is a fixed script (`panel.py`) run by `/usr/bin/osascript`. Nothing is inserted into the script: provider names, labels and states are passed as arguments. Its output is parsed strictly (each of the five providers exactly once, `on` or `off`); anything else, Cancel, an error or the 10-minute timeout changes nothing.
  - The *Foundry prices…* window is a second fixed script in `panel.py`, run the same way. Deployment names (from `foundry-deployments.json`, checked with the Azure name rule), notes and current prices are passed as arguments. Its output must be one JSON array with exactly one entry per row shown, each five strings of at most 40 characters; it is matched to the deployments by position, so no name comes back from the window. A changed field must be ASCII digits with an optional `.` or `,` decimal part, at most 10,000 (no `nan`, `inf`, exponents or other digits), or empty (no price); anything else shows the window again, without writing. Cancel, an error or the 10-minute timeout changes nothing. `--set-price` takes the same values and refuses anything else before it opens `config.json`.
  - The menu bar strip (gauge and rings) is a third fixed script, in `ring.py`, run the same way with a 5-second timeout. It gets only values that pass strict patterns before the run: one of the five gauge symbol names, a percentage or `–`, colour levels, whole percentages from 0 to 100, the fixed initials, and logo paths that can only be the fixed files in your logo folder or the included one (see *Files read*). It must answer exactly two lines of base64, each a complete RGBA PNG 44 pixels high, at most 800 wide and 96 KB, both the same width: each image's chunks and their checksums are checked, and its pixel data must unpack to exactly that size (unpacking stops there, so a crafted image can't grow past it); anything else, an error or the timeout means no image, and the menu bar shows the gauge and percentage as text. The images are re-encoded from the checked bytes, and checked again whenever they are read back from the cache.
  - The *Providers…* window's two settings come back as two more fixed lines (`gauge=on|off`, `ring_gemini=gemini|3p`), parsed as strictly as the provider lines.
  - Azure names from `config.json` are validated, because `az` expands `@file` arguments.
  - Microsoft Foundry runs only these `az` commands: `account show`, `cognitiveservices account show`, `monitor metrics list` (the token metrics, and in a separate call Azure's estimated-cost metric `FoundryModelEstimatedCost`) and `rest --method post` to Cost Management's read-only `query` endpoint. The Azure CLI makes the requests with its own sign-in; for Foundry the plugin opens no connection of its own.
- **Network.**
  - HTTPS only for remote services.
  - Requests to `127.0.0.1` bypass every proxy (environment variables and macOS system settings).
  - Redirects are never followed (urllib would forward the `Authorization` header).
  - Response bodies are capped at 1 MB. Codex's output is capped at 5 MB per exchange, under one deadline.
  - Error messages are replaced with fixed text, so headers can't leak through exceptions.
- **Menu output.**
  - SwiftBar turns ` | key=value` into actions (`bash=`, `href=` …), `--` into submenus and `---` into separators. Every external string therefore has `|` replaced and control, format and line-separator characters removed (including U+2028/U+2029/U+0085), runs of dashes collapsed, and leading dashes and combining marks removed.
  - The tooltip is quoted with quotes, backslashes and `=` removed.
  - The menu bar strip reaches SwiftBar only as `image=<light>,<dark>`, and only if both are plain base64 text; otherwise the title is the gauge and percentage as text.
  - The settings path of *Open settings* is quoted. A relative path, or one containing a quote, a backslash or a control character, is not shown at all.
  - Click targets are fixed in `render.py`: the provider usage pages, `open` on the settings file, and, for *Providers…*, *Menu bar shows* and *Foundry prices…* (also the Foundry section's *no price* line), this plugin's own launcher with `--choose`, `--show` or `--prices`. No provider text goes into a `--choose` or `--prices` click. A *Menu bar shows* entry carries a limit's name from a provider's answer only if the name passes a strict allow-list (an ASCII letter or digit, then also spaces, `.`, `_` and `-`, at most 30 characters, so no quote, backslash, colon or shell character); otherwise the entry has no action. `--show` accepts only a known provider and a name that passes the same allow-list, and refuses anything else before it opens `config.json`. The launcher path is quoted with the same rules as the settings path and must not contain shell characters (`' $ ; & | < >` or a backtick), in case SwiftBar's shell wrapper is ever used; if it (or a `--config` path passed along) would need escaping, the item is shown without an action.
- **Robustness.**
  - Provider results and cache files are normalised before use: NaN, text dates, missing fields and out-of-range values are dropped. Azure's estimated cost is a preview metric: a failed query, or a value that is missing, not a number, negative or implausibly large (over $1,000,000 a day per deployment), counts as no estimate and never breaks the Foundry section; a failed token query skips it.
  - Each section is rendered independently, and a top-level handler prints a fixed fallback menu. A broken value can't blank the menu or show a traceback with your paths; only `--debug` prints the traceback, to the terminal.
- **Files read.**
  - Claude: the Keychain item `Claude Code-credentials`; as a fallback, `~/.claude/stats-cache.json`.
  - Codex: as a fallback, the newest `~/.codex/sessions/**/rollout-*.jsonl` (only its last 2 MB).
  - Gemini: Antigravity's `~/.gemini/antigravity/daemon/hub_*.json`; as a fallback, `~/.gemini/oauth_creds.json`.
  - Marks for the menu bar rings, by names fixed in the code: your own files, if you put them there, `~/Library/Application Support/ai-limits-bar/logos/<provider>-light|-dark.svg|pdf|png` and `<provider>.svg|pdf|png`; otherwise the project's own drawings in `ai_limits/logos/` (`<provider>-light.pdf`, `<provider>.pdf`: vector PDFs made from the SVG sources in `ai_limits/logos/source/`, paths only, no scripts, links or embedded images). A folder or file that is a symlink, owned by someone else (an included one may also be owned by root), writable by group or others, or a file over 512 KB is skipped; a file's checks are made on the opened file (a link is not followed). A `.png` must be a PNG image of at most 2048 x 2048 pixels, which the plugin reads from the file's first 24 bytes (macOS would otherwise draw any image format under that name, at any picture size); otherwise it is skipped too. The plugin reads nothing else from these files: the drawing script opens them, as images. Two limits remain: an `.svg` or `.pdf` of yours is drawn by macOS as it is, so an image embedded in it is decoded too, bounded only by the drawing's 5-second timeout; and the drawing script opens the file again by its path, so the checks hold as long as nobody else can write to that folder (which they require).
  - `config.json` (or `config.example.json`).
- **Files written.**
  - `config.json`: created from `config.example.json` on the first run (0600), and rewritten when providers are turned on or off (the *Providers…* window or `--toggle`), the menu bar choice changes (`--show`), the gauge switch or the Gemini ring group changes (the *Providers…* window, `--gauge`, `--ring`) or Foundry prices change (the *Foundry prices…* window or `--set-price`; only the Foundry entry's `prices_usd_per_million` changes, and only the fields given). That is the only file such a change writes: in one atomic write (temp file in the same folder, then rename), under a lock, with its mode kept and a symlink kept as a symlink. A file that is not valid JSON is left untouched. Turning a provider off doesn't touch its cache; an off provider is not read at all.
  - The cache lives in `~/Library/Caches/ai-limits-bar/`. The folder is 0700 and the files are 0600, written atomically with `mkstemp`. A symlinked cache folder is refused.
  - The cache holds numbers, times and labels, including Foundry deployment and invoice meter names (see *Privacy*). `foundry-history.json` holds per-item amounts and, per deployment, monthly token totals and monthly totals of Azure's estimated cost only. `foundry-deployments.json` holds the names of the deployments with tokens but no Azure estimate, the token types each used, and those used today, this week or this month (no amounts), written after each successful Foundry token read, for the prices window; it is read back with the same checks as above. `providers-state.json` holds the names of providers the last menu update found not set up on this Mac, for the window's notes. `menu-bar-image.json` holds the last drawn menu bar strip: its two PNG images (the gauge, percentages and initials or your logos, as drawn) and a fingerprint of the values they were drawn from. `keep-values.json` holds a time and, after a price change, the provider name `foundry`: `--choose`, `--show` and `--prices` write it (also `--gauge` and `--ring`, from a terminal) so the refresh SwiftBar runs right after the click uses the values already read, whatever their age, and reads only a provider that has none yet and the one it names (not forced). It counts only if it is at most 10 seconds old and any name in it is a known provider; the next forced refresh deletes it whether it counted or not, and all it can do is skip that one re-read. A link cannot create it: only those command-line arguments write it.
  - *Refresh now* only asks SwiftBar to re-run the plugin (`refresh=true`); it runs no command.
  - No log files.
- **Privacy.** The menu never shows email, username, tenant or subscription id. Foundry's *Details* submenu and the *Foundry prices…* window list the model deployment names you chose in Azure, and Details also the invoice meter names (models and services); these are also stored in the cache. Nothing else from the Azure account (no subscription id, tenant, resource or resource-group name) is shown or stored.
